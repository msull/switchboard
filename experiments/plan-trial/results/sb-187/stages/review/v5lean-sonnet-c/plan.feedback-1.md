1. **`Cancelled` attempts as a source of the rerun input rest on nothing.** The plan (Actions §1, §3) accepts a `Workflow` attempt in `Failed` *or* `Cancelled`. The facts speak only of `fail_attempt_with` (Failed): facts.md:13 and :30. Nothing settles what a `Cancelled` review's file holds. The tree (`dispatch/src/ticket.rs:228-232`) says Cancelled is "Stopped by Dispatch (the ticket parked, a rerun replaced it, or a later gate sent the work back)". A review cancelled because the owner sent the work back can hold a copy the owner is discarding. Adopting it as the next review's subject, and listing it in `show`, is a behaviour change nobody asked for. The issue is about a runner failure. Restrict `holds_review_copy` to `Failed`, or cite what shows a Cancelled copy is wanted.

2. **A line reference does not match the worktree.** The plan cites `src/core/control.rs:865` as where the app answers `no such run`. In this tree `control.rs:865` is `pub fn run_view`, and the string is at `src/app.rs:3918` (with `src/app.rs:1895` for the pruned-log case) and `dispatch/src/scheduler.rs:8445` (`NO_SUCH_RUN`). Fix the citation.

3. **"The planner's file is the bytes it started from or a revision of them, so newest wins" is asserted with no support.** (Actions §1, second bullet). A review that failed mid-round may have left a half-edited copy, because the copy is edited in place until `finalize` (`ticket.rs:1446-1450`, the `shown_where` doc comment). Neither the facts nor the tree says a failed attempt's copy is a complete, coherent revision. The plan names no check that the file was last written at a round boundary. Say that this premise is unverified and that the rerun may review a partly edited copy. Then either state the accepted risk, or limit the pick to a failed attempt that has `revisions`, falling back otherwise. The plan's own chain scenario (review/2 fails with empty `revisions`) shows the cost of that limit, so choose one and name it.
