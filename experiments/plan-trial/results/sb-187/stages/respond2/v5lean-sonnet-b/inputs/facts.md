## Settled

Claims about the tree (closer read):

- A rerun of a workflow attempt takes its plan input from `review_subject`, which keeps only `Complete` attempts. A failed `review/1` is skipped and `plan/1` is copied again. — `dispatch/src/scheduler.rs:10534-10548`, called at `:7465`; copy at `:7458-7471`.
- The new attempt always gets its own directory: `attempt_dir` joins ticket dir, stage, `n`, ctx and only calls `create_dir_all`. — `scheduler.rs:6303-6317`. So a rerun never writes into `review/1/joined/`.
- Nothing removes or overwrites a failed or cancelled review attempt's directory. The only `remove_dir_all` over attempt data is `drop_evidence`, which deletes evidence dirs only (`scheduler.rs:10075-10081`; callers `:2447`, `:2539`, `:10436`, all at close or park-cleanup). The only `remove_file` of an artifact is `prepare_writes` (`:10141-10158`), for the attempt being started (a gate-only command's own artifacts, in its own dir). `restart.rs` has no `remove`/`rename`. The one other `remove_file` near review is the refused-`revise` cleanup of the feedback file (`scheduler.rs:7642`). The grep covered `dispatch/src/*.rs`. Queries: `grep -n "remove_dir\|remove_file" dispatch/src/*.rs`, `grep -n "remove\|rename" dispatch/src/restart.rs`.
- Round snapshots (`<data dir>/.../workflows/<run>/round-<n>/`, plan plus feedback and response files) are taken at the end of a reviewer round (`RunState::Converged`/`AwaitingResponse` transitions) and after the planner's response. — `src/core/workflow.rs:657`, `:669`, `:686-698`; `docs/design.md:1076-1082`. A reviser edit made after the last snapshot (the owner's `revise` round) is not snapshotted if the run dies before that round finishes. So `review/1/joined/plan.md` itself is the only durable copy of the revision, and it survives (previous bullet).
- `revise()` writes the owner's note to `review/1/joined/plan.feedback-<round>.md` before sending, and removes it only when Switchboard refuses (`scheduler.rs:7616-7642`). It survives a runner failure on disk. The note is not on the ticket record; `Revision` holds `round`, `by`, `at_ms` only (`dispatch/src/ticket.rs:510-516`).
- `Attempt.revisions` is pushed before the send (`scheduler.rs:7620-7624`) and popped only for a `Reply::Failed` that is not `NO_ANSWER` (`:11285-11313`, pop at `:11313`). A `NO_ANSWER` keeps it with the reply recorded as lost. So non-empty `revisions` on a failed attempt means the revise was sent or its fate is unknown, not that the reviser finished editing. Whether the run opened the round is separate evidence (the feedback file exists, since a refusal deletes it).
- The `Complete`-only readers of the `plan` name: `Ticket::input_where` (`ticket.rs:1452-1463`, used via `lane_input` at `scheduler.rs:10849` and `Ticket::input` in `serve.rs:587`), `Ticket::shown_where` (`ticket.rs:1476-1491`, used by `serve.rs:570` and `lane_files_by` at `scheduler.rs:10899-10925`), and `review_subject`. Existing tests pin only the complete and open cases (`ticket.rs:1819-1892`, `scheduler.rs:12836`). The investigation also names `report.rs` `plan_review` (`:355-380`), not re-read here.
- `rerun_carries` adds text only for `AttemptKind::Review` (and the resolution stage); a `Workflow` attempt's rerun question says nothing about which copy is reviewed. — `scheduler.rs:9382-9390`.
- A park then resume hits the same path: a cancelled workflow attempt is rerun through the same `review_subject`. — `scheduler.rs:9363-9368` per investigation, same predicate.
- The app's rerun clone uses `source` = the session that wrote `plan/1`, not review/1's planner. — `src/core/workflow.rs:289`; investigation notes 4. The owner's note went only to the review run (`ObjectWorkflow`, `src/core/workflow.rs:969-1000`). So the clone cannot see the revision by transcript; only the file carries it.
- `LaneFile`/`PathsView` are built in `dispatch/src/serve.rs`; `show` prints them at `dispatch/src/main.rs:~896-993`. A new field there is a wire change in the dispatch control types and must be additive (CLAUDE.md, "Extending the contract").
