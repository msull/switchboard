1. **`rerun_copy` assumed the newest failed review held the newest plan.** Agreed, and the plan changed in "The record", "The actions and effects" item 1, and "The tests". `rerun_copy` no longer uses `latest_attempt`. It walks `t.attempts` backwards. A `Complete` attempt of any stage with the subject artifact (the `review_subject` filter) ends the walk with no failed copy. A `Failed` workflow attempt of the same stage and context with the artifact and an existing file is the failed copy. Everything else is skipped. Vector position orders attempts across stages, since `n` is per stage. `review_subject`'s `.rev()` already relies on the vector being chronological. A failed `review/1` followed by `plan/2` now loses to `plan/2`. The unit test covers both orders: failed `review/1` then complete `plan/2` gives `None`, and complete `plan/2` then failed `review/2` gives the failed copy. The plan says I read the code only and did not run a restart to see whether `plan/2` can follow a failed review in a real ticket. I did not add a `first_slice.rs` scheduler test for this case, because I have not shown a real ticket can reach that order. The unit test carries it either way.

2. **`rerun_copy` and the `ticket_paths` rule were two signatures.** Agreed; changed in "The actions and effects" items 1–3, "The UI", and "Contract additions". There is now one function: `rerun_copy(t, stage, ctx, subject, before: usize) -> Option<PathBuf>`. `before` is the index in `t.attempts` of the attempt being started or shown, and only attempts before that index are considered. `start_workflow` and `rerun_carries` pass `t.attempts.len()`, because the next attempt is not pushed yet. `ticket_paths` passes the open attempt's own index, so it can never find itself. "The record" now says the "cannot drift" claim rests on this one function. The tests include `before` set to the failed attempt's own index returning nothing for it. The `serve.rs` test also covers a complete `plan/2` sitting between the two attempts.
