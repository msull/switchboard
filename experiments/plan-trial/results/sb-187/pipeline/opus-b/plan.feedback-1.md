1. The Docs section leaves out `docs/dispatch.md`, which is Dispatch's own spec (`docs/design.md:1522` points to it). The change contradicts it. "A review is a copy" (`docs/dispatch.md:550-557`) says a workflow stage "copies the reviewed artifact into its own attempt directory", but after this change a rerun copies the failed attempt's copy instead. That paragraph needs the new rule and the "start over" escape. The first-slice table is where every Dispatch behaviour and its test name are recorded; see the `revise` row at 2975 and the review-code carry and "start over" rows at 3058/3060. It needs rows for `a_rerun_after_a_failed_review_reviews_the_revised_copy` and `a_start_over_rerun_reviews_the_plan_stage_output`. The `show` paragraph near 2834 should also name the new `from` line. Updating only `design.md:1785` leaves Dispatch's spec describing the old input.

2. Step 1 of `start_workflow` takes the note off `t.rework` before anything that can stop the launch. `start_workflow` can still park on "names no reviewer", "names no subject", or a `review_subject` error (7449-7467), or return `Err` from `attempt_dir`/`std::fs::copy` (7468-7472). In all of these the note has already been removed. The scheduler's convention is that a note "is taken off only with the attempt that carries it: a launch that stops short ... keeps it" (`scheduler.rs:6279-6281`, removed at 6370 after the push). The plan should read the note with `t.rework.get` to decide `starts_over`, and remove it only when the attempt is pushed (7489).

3. The plan says "No app change", but the app's ticket page Plan tab still loses the owner's revision. That tab lists "the plan review's rounds" (`docs/design.md:2163-2165`) from `PathsView.plan_rounds`. `ticket_paths` builds `plan_rounds` from the newest Workflow attempt that has artifacts only (`dispatch/src/serve.rs:564-572`). Once review attempt 2 starts, review/1's rounds disappear from the page, including the owner's `plan.feedback-<k>.md`. Only `show` gets the new `from` pointer, and nothing in `src/ui/ticket.rs` reads `plan_files`. The issue asked for the earlier copy to be visible next to the reviewed one. The plan must either carry `from` (or the earlier attempt's rounds) to the Plan tab, or list this as a known gap in the design status.

4. The plan does not say what happens when the failed attempt's copy is incomplete. The failures this targets include "its reviewer or planner exited or stopped without its round file" (`docs/design.md:1782-1784`). In that case the copy may hold an edit the dead planner only partly made. Today a rerun starts from the clean `plan/1` output. After this change it silently starts from whatever is on disk, and the rerun question only advertises "the owner's revision of round {k}". The plan should state this behaviour: either as a known gap with "start over" as the remedy, or by having the rerun question say that the copy is the one the failed run left.

5. The `rerun_carries` wording says "`{writer}/{n}` is the attempt that `review_subject` names". `review_subject` (`scheduler.rs:10534`) returns `(PathBuf, String)`, the path and session, not the attempt, so no stage or number is available to print. The plan needs to name the change that provides it: for example, split out a helper that returns the `&Attempt` and have `review_subject` and `rerun_carries` both use it. Otherwise the question text cannot be built as specified.
