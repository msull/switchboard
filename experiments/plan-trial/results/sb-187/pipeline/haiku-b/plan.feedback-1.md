1. **A failed review that the owner parks keeps its revised copy as the plan, which the plan does not address.** `park` cancels only open attempts (`scheduler.rs:2872`, `:2914`); a `Failed` attempt stays `Failed`. The new rule (`Failed` with non-empty `revisions`) therefore makes `shown` return the revised copy for a parked ticket. A review cancelled while running returns `plan/1` (the plan's own test). Decision 2 covers only `Cancelled`. Either extend the rule to exclude parked tickets, or add a decision and a test for "failed, revised, parked". The existing comment at `ticket.rs:1856` ("A parked review's copy is not the plan going forward") states the principle the plan breaks.

2. **The change to `shown_where` is not stated.** The "Actions and effects" section adds only `Ticket::review_copy`. The Tests section requires `shown` to return the revised copy, and `PathsView.plan`, `shown_lane_files` (`scheduler.rs:10919`) and `ticket_paths` (`serve.rs:570`) all read `shown_where`. So `shown_where` itself must accept a `Failed` workflow attempt with revisions, or those readers stay on `plan/1`. Say so, and say whether `review_copy` and `shown_where` share one predicate. `shown_where`'s doc comment (`ticket.rs:1471`–`1475`) also needs updating.

3. **The rerun question can state something false.** The plan says the clause reads "with the owner's revision", and in the same document says the revision reaches the copy only if the reviser applied it before the run died. Make the clause conditional, or drop "with the owner's revision" and name the file so the owner can check it.

4. **The rerun clause names the wrong attempt.** `rerun_carries(t, stage, n)` (`scheduler.rs:9382`) takes no `Pipeline`, so it cannot learn the subject, and it is called with the failed attempt's `n`. `review_copy` can return a different attempt. Example: `review/1` is `Failed` with revisions, and `review/2` is `Failed` with none. `review_copy` then returns `review/1`'s copy, but the clause would say "the copy review 2 left". The plan must say which attempt the clause names, how the subject is found (for example, the attempt's own `artifacts` keys), and that the revision condition is checked on that attempt.

5. **Docs the plan leaves out or misstates.** `docs/design.md:2533`–`2537` says `plan_files` "shows an open review's copy" and that agents and `show` differ in a way the plan changes. `docs/dispatch-agent-guide.md:213`–`214` documents the `show` lines `(reviewed copy, round N, review open)`. The plan adds `(prior revision, round N)` and `(reviewed copy, round N, review not open)`, and the agent guide must describe them. The plan's doc list (design 1784–1787, 2163–2165, 3672, CHANGELOG) omits both.

6. **The contract addition is not handled as CLAUDE.md requires.** `src/ports/dispatch.rs:11` re-exports `PathsView` and `LaneFile` from `dispatch_control`, so `LaneFile.prior` is part of a shared contract. CLAUDE.md says a contract addition is additive and that the commit message says what was added. The plan's commit message is a title only. The plan should also say why no schema bump is needed: `PathsView` and `LaneFile` are serialized over the port and `show --json` but stored in no record (checked: no record type holds them), so `RECORD_VERSION` stays at 28.

7. **Existing `LaneFile` literals need changing, which the plan does not say.** The plan says "existing literals take `..LaneFile::default()`". The `plan_files` literal at `serve.rs:541`–`548` has no `..`, so it needs `prior: false` added. Only `notes_files` (`serve.rs:551`–`558`) uses `..LaneFile::default()`.

8. **The `prior` entries cannot get their lane from the helper the plan names.** The plan says to "give it the lane `lane_files_by` gives that attempt". `lane_files_by` with `shown == false` (`scheduler.rs:10908`–`10925`) and `lane_files` pick only `Complete` attempts, so a `Failed` attempt is never returned. Either add a picker that accepts failed revised attempts, or say how the lane is found. The `PathsView.plan_files` and `LaneFile` doc comments (`dispatch-control/src/lib.rs:547`–`549`, `:574`–`578`, `:586`–`600`) say `plan_files` is "the plan as it stands", and adding prior revisions changes that. Update them.

9. **The `show` label change applies to every finished plan review, not only failed ones.** The rule "round is `Some` and `reviewing` is false" prints `(reviewed copy, round N, review not open)` for any finished review's copy. That changes today's output for normal runs. Either restrict the label to the failed case or name the change, and include it in item 5's doc update.

10. **The unit test is not optional.** The plan says to add a unit test for the three `print_lane_files` labels "if main.rs has a tests module". It does: `dispatch/src/main.rs:1898` has `#[cfg(test)]`. The plan should require the test and place it there.
