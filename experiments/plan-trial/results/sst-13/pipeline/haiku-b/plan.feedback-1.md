1. **`update(id)` keeps the false conflict, so the fix does not cover the path the plan says it covers.** Section 2 says `ResourceRepository.update()` goes through the fixed latest-version read. That holds only when an object is passed. With an id, `update()` calls `self.read(id)` (`extras/repository.py:178`), which goes through `_get` (`:356`): the repository cache, then `self.ddb.get_existing(id, model)` with the default `consistent_read=False`. So a write that lands and is followed by `update(id, ...)` still gets a stale pre-image from `read()`, and `update_existing` then raises `VersionConflictError` at `dynamodb_memory.py:578`. Either make the pre-image read in `update()` strongly consistent (and decide whether it bypasses the cache, as `save` does), or narrow the claim in Section 2 and the CHANGELOG entry to say that `update(id)` is not fixed.
