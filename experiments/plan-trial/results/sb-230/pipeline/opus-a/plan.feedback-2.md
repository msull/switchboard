8. New, arising from 2: `hostname -s` is not the name macOS answers for over mDNS. The responder publishes `LocalHostName` (`scutil --get LocalHostName`, or `SCDynamicStoreCopyLocalHostName`). `hostname -s` returns the short `HostName` when one is set, by the owner or by DHCP or reverse DNS on some networks, and that can differ from `LocalHostName`. The Bonjour record does not prove the name resolves either: `src/adapters/bonjour.rs:41` registers `<hostname -s>.local.` with an empty address list, so it publishes no A record and relies on mDNSResponder already owning that name. When the two names differ, the QR's URL does not resolve. On this Mac the two names are equal (`HostName` is not set), so the spike would pass here and miss the problem. `local_host_name()` should read `LocalHostName` (for example `scutil --get LocalHostName`, run once, `cfg(target_os = "macos")`, falling back to the LAN IP elsewhere or on failure), and the spike should record both names.
