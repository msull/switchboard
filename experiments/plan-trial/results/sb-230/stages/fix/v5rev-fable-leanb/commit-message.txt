The core decides the invite's address, the page recovers from an unreachable host and tells a refused cookie from a removal, and the slot test holds its connections open

core::remote::invite_address and InviteAddress decide where the invite points (the network address while the port listens there, loopback with a reason otherwise), and invite_url takes that, so the dialog's address line and the QR code come from one value; the dialog now says when no network address was found instead of showing nothing. The page restores the list or session on the first reply after a "can't reach the host" notice, says "paired, but the cookie did not come back" when /me is 401 right after a 200 /pair, clears any fragment before parsing it, and treats a fragment that does not decode or is not a whole invite as an incomplete link. The cookie name is built in one place and read by authenticate, which borrows the token; origin_is_own is a method on RemoteRequest. page_loads_free_their_slot_and_have_a_window_of_their_own holds four read page connections open and still reaches /info, which fails if the connection thread keeps reading, and an upgrade asked of a page path is answered as the page.
