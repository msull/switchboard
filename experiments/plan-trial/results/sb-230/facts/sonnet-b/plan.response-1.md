# Response to plan.feedback-1.md

All edits are in `review/1/repo/plan.md` and were re-read in the file after the edit.

1. **Paired pool.** Changed: "The signals", new bullet "The paired pool". The page sends all its `fetch` calls through one queue with at most two in flight, so with the WebSocket a tab holds at most three connections and normally two. A 503 `full` is shown as "too many connections, close other tabs" and retried with back-off, never as revoked; only a 401 on a request that carried a token is "revoked". `MAX_PAIRED` is not changed. The fallback, if one phone and one tab still hit `full`, is raising `MAX_PAIRED` and the 16-connection total together in a follow-up. The Node tests now cover the 503 case and the in-flight bound. The plan states that nothing in the facts says the connections fit.
2. **Rate limiting contradiction.** Changed: "The signals", the first bullet. The rate check stays first in the request loop (`:788`). `Limits::limited` (`:631`) maps the three page paths to the `page` window, and the static branch runs after it. "Before the rate check" is gone.
3. **CSP and inline style.** Changed: "The record" (Decision 2, the defence bullet) and "The tests" (adapter units). The page changes appearance only with `classList`. The test bans `setAttribute('style'`, `cssText` and `.style.` in `app.js`, as well as `style=` in the HTML. The plan says this is a premise of the plan, not a fact from the facts file.
4. **Click-through promised as fact.** Changed: "The record" (Decision 1), "The UI" (dialog hint), "Docs" (changelog and the `docs/design.md` bullet). The dialog says that a browser warns and, if it lets the owner continue, to do so on this address only. The changelog line no longer promises the click-through and says it is not yet tried in a browser. The `design.md` gap bullet states the untried points: click-through per browser, the exception surviving an address change, hand-built responses, and the camera app seeing the code. It also names the written fallback.
5. **Device name.** Changed: "Where this departs", the `device_name` bullet, and "The tests" (core). `new_device` now drops control characters before the 64-character take, with a core test. The name reaches three places, all checked: the dialog (`src/ui/remote.rs:242`), the pairing log line (`src/app.rs:3666`, formatted with `{:?}`, which escapes) and the new `/me` reply (JSON, escaped). There is no `/devices` listing endpoint, and the Swift client only sends a name (`ConnectionManager.swift:371`), never reads one.
